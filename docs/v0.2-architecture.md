## 2. Quyết định stack UI

**Chọn Option A: Electron + SolidJS**, nói chuyện với Core qua **AG-UI** (không qua IPC riêng).

| Tiêu chí | A: Electron + SolidJS | B: Electron + React + CopilotKit |
| --- | --- | --- |
| Giữ UX OpenBot | **Cao**: dùng lại hợp lệ design tokens + CSS + avatar của OpenBot v0.1.11; cùng mô hình component với OpenBot mà người dùng quen; fork AIKINGX_Bot hiện tại cũng là Solid | Phải vẽ lại toàn bộ từ shadcn; component CopilotKit có "vibe" CopilotKit, không phải OpenBot |
| Tốc độ phát triển | Nhanh cho shell nhỏ (prototype v0.2: 1 file App + client AG-UI, bundle 27 kB) | Nhanh hơn nếu dùng nguyên CopilotKit chat — nhưng lúc đó UX là của CopilotKit |
| Maintenance | Ít dependency (solid-js, vite) | Nhiều (React, CopilotKit runtime, shadcn, TanStack…); runtime CopilotKit đi kèm khái niệm Intelligence |
| Nâng cấp | AG-UI là ranh giới: có thể thêm client React sau mà không đổi Core | Gắn vào vòng phát hành của CopilotKit |
| Tái sử dụng code hợp lệ | OpenBot v0.1.11 (Apache-2.0) | Component MIT của CopilotKit |

Vì UI chỉ phụ thuộc giao thức AG-UI, nếu sau này cần component CopilotKit (ví dụ generative UI) thì vẫn
gắn được một client React vào cùng gateway — quyết định này không khóa đường lui.

## 3. Kiến trúc mục tiêu và phần đã có

```
AIKINGBOT Shell (SolidJS; web hôm nay, Electron ở phase sau)       apps/shell
        │  AG-UI over HTTP + SSE (RunAgentInput → events; interrupt/resume cho approval)
AIKING Gateway + AG-UI Adapter                                      src/gateway
        │  AgentBackend interface  ← điểm thay Runtime
AIKING Core: ChatSession, AgentRuntime, ToolRegistry + PermissionGate,
             CapabilityIndex, SkillLibrary, McpHub                  src/{chat,runtime,capabilities,skills,mcp}
        │  ModelClient interface   ← điểm thay provider
Model providers (Claude adapter; Offline demo; FallbackModel)        src/runtime, demo/offline-producer.ts
MCP servers (stdio) / Skills (SKILL.md)                             demo/
        │
SQLite (agents, threads, messages, runs; migrations; backup)        src/store
```

| Yêu cầu (mục 3 của brief) | Trạng thái |
| --- | --- |
| 1. UI/UX tinh thần OpenBot | Prototype web: sidebar agent + threads, chat streaming, timeline, approval, skills — có, chạy được |
| 2. Runtime độc lập UI | Có: UI chỉ nói AG-UI; `AgentBackend` là ranh giới |
| 3. Multi-provider | Có interface + Claude adapter + fallback chain; chưa có adapter OpenAI/Gemini |
| 4. Skills/MCP là capability khám phá được | Có (`plan_capabilities`, catalog trong UI) |
| 5. Computer runtime tách khỏi remote | Chưa làm (phase sau; ứng viên: `agent-computer` của CopilotKit OpenBot, MIT) |
| 6. Background jobs resume sau crash | Một phần: run đang chạy khi crash được đánh dấu `interrupted`; chưa có hàng đợi job |
| 7. Permission boundary + approval | Có: risk read/side_effect/dangerous, approval qua AG-UI interrupt |
| 8. Data thuộc AIKING, backup, migration | Có: SQLite local, migration đánh số, `backup()` (VACUUM INTO) |
| 9. Module/plugin | Một phần: skill = thư mục, tool = MCP server; chưa có cơ chế plugin cho UI |
| 10. Không phụ thuộc một cloud trả phí | Có: chạy offline hoàn toàn; Claude chỉ khi `--live` |
