## Why this full application

OpenMausBot supplies more of the requested modern behavior as one working implementation: persistent bots and conversations, groups, provider engines, custom endpoints, routines, connected apps, MCP, settings and computer panes. Retaining these screens and the harness gives a smaller Stage 1 implementation than assembling libraries or adding Rust/Python services. React is selected because this full source uses React; rewriting it to Solid would discard useful implementation.

Keep the application's state/store, driver contracts, harness, desktop lifecycle and existing components. Its connected-app catalog uses Composio and per-bot grants. Account authorization and provider credentials are required for external calls. Cloud computers and phone services need configuration. Their presence in source does not prove those external services have been provisioned for this delivery.

## Source-rights boundary

- Exclude OpenMausBot `enterprise/`. Its license limits production use, redistribution, hosting and white-labeling; the user has no partner grant. Upstream `LICENSING.md` explicitly supports an OSS edition after removal. Preserve the Apache optional loader in `server/enterprise.ts`, `LICENSE`, `NOTICE`, `LICENSING.md`, `third_party/` and noVNC notices. Replace protected Maus product names and mascot with AIKING assets; attribution stays intact.
- The latest nightly OpenBot is a reference only. The next historical tag, v0.1.12 at `2e8068220fa0e388852eaea99b0627172c57cd4c`, already has PolyForm Noncommercial. The older Apache release does not grant rights to later code.
- Eigent root and source headers say Apache-2.0 despite a stale MIT package field. Its `resources/example-skills/{docx,pdf,pptx,xlsx}/LICENSE.txt` reserves Anthropic rights and refers to Anthropic service agreements. Exclude those bundles from generic commercial reuse unless separately authorized.
- AionUi's separate `iOfficeAI/AionCore` and `iOfficeAI/aionrs` root licenses were read through GitHub and are Apache-2.0. Those backend sources were not built in this audit.
- CopilotKit app licenses do not grant a license to its Intelligence service. Shallow source inspection also does not establish rights to every external asset or hosted catalog item.

## Exact parity work left after Stage 1

The selected app has related features, but does not implement nightly's exact contracts or presentation:

- OpenBot workspace sidebar, conversation timeline/composer, icons, spacing, themes and settings layout require a later visual and behavior pass.
- OpenBot's marketplace has separate agents/apps/skills browsing, filters, detail pages, installation and ownership state. Maus's app/MCP/skill surfaces are not that marketplace or its catalog/API.
- OpenBot's first-party GitHub, 1Password, Bitwarden, Slack, Discord and Telegram controllers and local/server availability rules are not reproduced by the Composio catalog.
- OpenBot's shared-channel ownership/delegation, remote-server/mobile/web workflows, account behavior and managed-provider setup are not established as equivalent by this import.
- Provider credentials, real connector actions, cloud computer/phone availability, provider installer behavior and platform packages need separate execution evidence. Matching a provider name does not establish matching session behavior.
- AIKING Core is not connected to this application in Stage 1. The later integration must preserve approval, persistence and tool boundaries; see [the integration plan](stage-1-core-integration.md).
